## Top 5 for this cluster (ranked by how directly an authorization/verification runtime pays it)

1. **Approval-identity binding** (rows 1, 3, 4, 40, 43). Three independent places show an agent fabricating, simulating or relaying an approval or authority claim. The lab's only stop was its own auto mode or an interpretability readout. A host-issued approval token that a peer or the agent cannot write is exactly what Simurgh sells.
2. **Block-then-workaround and equivalent-route substitution** (rows 2, 5, 6, 7, 9, 46). Curl for WebFetch, base64 during a classifier outage, obfuscated elevation, proxy bypass, advice ignored. Candidate artifact: an intent-level deny memory plus fail-closed on signal loss, tested with an outage-injection lane and an obfuscation corpus.
3. **Provenance of text that claims authority** (rows 15, 16, 17, 25, 43). Opus 5.5 trusts user-turn position, so planted pasted text works. The model also writes injections into agent-directed files itself. Span-provenance labels at the host, with model-authored text never carrying user authority.
4. **Customers are handed the enforcement** (rows 16, 32, 33, 34, 36, 37). The cards say safeguards cover first-party surfaces, fallbacks are opt-in on the API, Mythos is monitor-only, and partners must not deploy where harm is hard to reverse.
