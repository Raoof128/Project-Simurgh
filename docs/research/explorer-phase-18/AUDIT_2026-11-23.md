# Audit of the evidence explorer, 23 November 2026

The owner asked for a full audit of the dashboard because it did not cover the lanes built
since it was written. This page records what the audit found, what was changed and what is
left. The scope of the change was declared first, in
[the Phase 18 page](../CONTINUATION_PHASE_18.md#phase-19-coverage-declared-23-november-2026).

The server's limits were read again and left alone: loopback only, `GET` and `HEAD` only, a
host check, an origin check, a content policy that loads nothing from elsewhere, and paths
resolved inside the build directory. The existing tests of those limits pass unchanged.

## What was changed

- **Every pack is a lane.** The tool reads the lane table of the operator handoff and, for
  each lane, the pack's receipt, report and protocol and the lane's two pages. It shows the
  summary, each prediction with its outcome, the stated limits, models, metered spend, the
  root and the verify command. Nothing about a lane is typed into the tool.
- **A record of predictions.** One view draws every prediction of every lane as a mark and
  lists the ones that failed with what was declared and what was observed.
- **Replication.** One view lists the thirty-one verify commands and marks which items an
  outside operator has run. The status is the handoff tool's own recomputation.
- **Open work.** The current list is read from the repository's README. The October register
  stays, labelled as a dated snapshot.
- **Library.** Lane pages, results pages, the ledger, the served-model census and the receipt
  index are searchable beside the October documents.
- **Layout and colour.** Data starts at the top of each view. Held is blue and did-not-hold is
  orange, and each state also has its own shape or word. A dark scheme follows the system
  setting. On a narrow screen the lane table becomes a list.
- **Links.** `#lanes/19ae` opens one lane, and the back button works.
- **Command line.** `lanes`, `lane`, `handoff` and `open-work` return the same data the
  browser shows.

## Second pass, the same day

The owner asked for three more things: an end-to-end run that shows every lane is covered,
proof that nothing is typed into the tool, and a front end that matches the project's logo.

### End to end in a real browser

`tests/e2e/browser.e2e.mjs` mocks nothing: it serves the built app with the real server and
drives Chrome over its debugging protocol. Ten parts pass. It opens every lane and compares
the page with the lane's receipt and root file, then uses the filters, the search, the Back
button and the keyboard.

It found two defects that the earlier tests had missed, both now fixed:

- Lane 19u's receipt keys its models by run, so the lane listed four models seven times.
  With repeated names on the page, opening another lane left some of the previous lane's
  model names on screen.
- The page of lane 19f was in the library twice.

A bundle with a repeated model or a repeated document is now refused. The test's own contrast
check was also wrong at first and found nothing; the pale line it plants as a control showed
that, and the check was repaired before its result was used.

Three tests hold this in place. One reads the tool's source for a lane id, a declaration id, a

a lane or listed as a folder without a pack: the handoff, the hosted receipts and the

What the tool still knows is the shape of the files: the names of receipt fields, the heading
of a results table, the paths of the ledger and the served-model page.

## Third pass: what would make it more useful

The owner asked whether the dashboard should do more, judged by what a reader at a lab would
find useful and new. Three sources were read: the project's gap hunt of 22 November, the
project's own open work, and what the field published in 2026 about reading agent evidence.

What the field's tools do is show: the UK institute's
[Transect](https://www.aisi.gov.uk/blog/transect-making-large-scale-agentic-evaluations-easier-to-understand)
turns a long transcript into a report in which a reviewer can jump from a finding to the
passage behind it, and a
[note from the US centre](https://www.nist.gov/blogs/caisi-research-blog/analyzing-transcripts-ai-agent-evaluations)
and Anthropic's
[guide to agent evaluations](https://anthropic.com/engineering/demystifying-evals-for-ai-agents)
both press for reading the record and not only the score. None of those pages describes a viewer in which the reader checks the
evidence's integrity, or one that scores a project's own predictions. That is a statement about
one search, not about the field. Three things were built from that.

- **The reader can check a pack where they read about it.** The page recomputes a pack's
  root and every member's hash in the browser, for one lane, for all of them, or for a copy
  from a file. On the author's laptop all thirty-one packs take about a quarter of a second.
  It reports a match or what differs and never the word verified.
- **The project scores its own predictions by subject.** One table splits them by whether the
  lane ran a model. On 23 November it reads: 27 of 37 held where no model ran, 17 of 24 where
  one did, and predictions decided model by model held in 35 of 138 cases. The author's
  predictions about models are the ones that fail.
- **Each outcome names the bytes that record it.** A prediction in a lane's view carries the
  file and the place in it, so a reader can go from the mark to the field.

Considered and left for the owner:

- A map from the pains the labs published in 2026 to the lanes that address them. The gap
  hunt holds it, and it is kept privately; publishing it is the owner's decision.
- The rows inside a Phase 19 pack laid out as a table, as the transfer study has. The page
  now lists a pack's members and shows the start of any one as text, which is the pack's raw
  content and not a reading of it.

Two smaller things from the same list were then built. A lane's view says whether its pack
holds a model id the provider returned, read from the repository's served-model census. And
after a lane's pack is checked in the browser, the page lists its members and shows the start
of any one the reader picks.

## Fourth pass: an agent as the reader

The owner asked that an agent be able to use the tool as a person uses the dashboard, with a
watcher in mind.

- **A command for each view.** `record`, `lanes`, `replicate`, `outcomes`, `library` and
  `open-work` return what the six views show, with `lane`, `inspect`, `doc` and `check` for
  one item. `commands` lists them with their arguments. The page and the command line take
  their list of views from one place, and a test fails if a view has no command.
- **A watcher.** `watch` hashes every pack and, given a snapshot it wrote earlier, reports
  what changed. It exits 3 when a pack does not hash to its root or when a root, an outcome
  or a lane differs from the snapshot, and 0 when the only changes are news.
- **Tools.** `cli.mjs mcp` serves the same commands as read-only tools over standard input and
  output. A tool takes no file path.

Every answer carries a line saying that text inside the evidence is data and not an
instruction. That line is a notice to the reader; it does not stop a careless one.

## What is left

- Lanes 19w and 19x record what was said beforehand only as a table on their results page.
  The tool reads that table and labels the outcome as read from a page. A receipt field would
  be firmer; adding one means a new pack, which this change does not make.
- Lane 19o repeats the hypotheses of lanes 19k and 19m and does not word them on its own
  page, so the tool shows their ids and counts without wording.
- Five early lanes (19a, 19b, 19c, 19e and 19g) have no dated ruling in the ledger and are
  shown as undated.
- The bird is a raster cut from a raster logo; the repository has no vector of it. The
  wordmark is live text in a system face and is not the logo's own lettering.
- The browser test was run in Chrome. Firefox and Safari were not run.
- The tool shows packs, predictions and a pack's raw members. It does not lay out the rows
  inside a Phase 19 pack as a table, as it does for the transfer study.
- The tests run only when someone runs them. A hosted job would need its own declaration.
- Nobody outside the project has reviewed this tool.
