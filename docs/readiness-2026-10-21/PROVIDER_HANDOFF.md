# Provider and independent-validation handoff

Owner/classmates own independent reproduction. All artifacts below are local preparation, not an
outside receipt. An OpenAI Admin credential must remain in the operator's credential manager or
secret environment; never put it in a report. The current process cannot complete lifecycle testing:
the original credential returned 403 for organization projects and 401 for bounded inference.
The later [uploaded-credential diagnostic](REFUSAL_FOLLOWUP.md) established inference access,
but did not test administration, revocation or alerts.

For an owned disposable test project, retain these acceptance records:

1. Pin the Simurgh source revision, protocol, archive root and outside operator identity. Run the
   [current replay runbook](../research/transfer-phase-17/RUNBOOK.md) and save complete command exits.
2. Record project ID and disposable service-account/key ID, permitted scopes, approved receiver and
   declared budget. Establish one authorized, harmless receiver effect before the lifecycle change.
3. Exercise scope reduction, rotation, expiry and revocation separately. Record admin request/result
   IDs and timestamps, subsequent authorization decisions, cache propagation interval and receiver
   effects. Preserve all probes, including admitted work and unknown acknowledgements.
4. Authenticate an alert fetch/delivery; retain producer and receiver evidence. Check wrong project,
   stale/replayed alert, lost delivery and disconnected receiver. A submitted alert is not delivered
   evidence, and a simulator cannot establish the provider's behavior.
5. Run keyboard/focus/zoom/contrast and real browser parity on a host that permits local fixtures.
   Save browser/version, failures and results. Do not bypass a managed browser policy.
6. Compare results against the declared acceptance contract, report differences and clean up only
   the disposable resources created for this test. Do not revoke an existing production credential.

The owner-authorized [refusal diagnostic](REFUSAL_PROTOCOL.md) uses four frozen requests and stops
on the first API error. Its original run is retained. Any rerun needs a new output directory and a
separately declared budget; it must not overwrite or selectively replace these outcomes.
